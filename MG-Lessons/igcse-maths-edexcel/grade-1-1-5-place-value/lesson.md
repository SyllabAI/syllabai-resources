## What place value means

![Place value chart of 36.482 showing columns from ten-thousands to thousandths and the value of each digit](../assets/001-03599b7c-4424-4fb5-aa44-c482472fd3b4.jpeg)

A digit is one symbol from $0$ to $9$, but a number can have many digits. Place value means the value a digit has because of its position in a number.

In $36.482$, the $3$ is worth $30$, the $6$ is worth $6$, the $4$ is worth $0.4$, the $8$ is worth $0.08$, and the $2$ is worth $0.002$. Digits further left have greater value, while digits further right after the decimal point have smaller value.

## Whole numbers and placeholders

Whole-number columns go ones, tens, hundreds, thousands as you move left. To find a digit's value, name its column, then multiply by that column value.

Worked example: in 2,794, count from the right. The 4 is ones, the 9 is tens, the 7 is hundreds, and the 2 is thousands, so the 7 is worth $7 \times 100 = 700$.

Zeros are placeholders that keep digits in the correct columns. In 8,041, the 0 sits in the hundreds column, so the 4 is in the tens column and is worth $4 \times 10 = 40$, not 400.

## Decimal place value

After the decimal point, the first place is tenths, the second is hundredths, and the third is thousandths. Read these columns carefully from left to right.

Worked example: in 48.263, the 2 is tenths, the 6 is hundredths, and the 3 is thousandths. So the value of the 6 is $6 \times 0.01 = 0.06$.

Adding zeros at the end of a decimal does not change its value. For example, $0.5 = 0.50$ and $1.6 = 1.600$.

## Building numbers and writing millions

If a question says "make a 5-digit number with 6 as the thousands digit", think in columns. The first digit cannot be 0, or the number would not really be a 5-digit number.

One possible answer is 76,421, because the 6 is in the thousands column and appears only once. This same column thinking helps when writing large numbers in figures.

A million is $1\,000\,000$. So 7 million is 7,000,000, and

$$$4.6 \times 1\,000\,000 = 4\,600\,000$$

so 4.6 million is 4,600,000.

## Ordering whole numbers and decimals

![Decimal comparison table rewriting 0.42, 0.402, 0.24, 0.024 and 0.204 to three decimal places before ordering them](../assets/002-fb75c035-6996-47d7-8372-0524ca0928a3.jpeg)
For whole numbers, compare from left to right. If one number has fewer digits than another, it is usually smaller.

For decimals, line up the decimal points and add zeros if needed. This lets you compare the same place values fairly, so a longer decimal is not automatically larger.

Worked example: order 0.42, 0.402, 0.24, 0.024, and 0.204. Write them as 0.420, 0.402, 0.240, 0.024, and 0.204, then compare from left to right, giving $0.024 < 0.204 < 0.24 < 0.402 < 0.42$.

## Digit cards and smart choices

To make the largest number from digit cards, put the largest digits in the highest-value columns. For example, from 6, 1, 8, and 4, the largest 3-digit number is 864 because 8 goes in hundreds, 6 in tens, and 4 in ones.

To make the smallest whole number, put the smallest digits first, but never start with 0. If you are making two 2-digit numbers and adding them, the tens columns matter more than the ones columns.

Worked example: using 1, 5, 7, and 3 to make two 2-digit numbers with the smallest possible sum, put 1 and 3 in the tens columns. One arrangement is $15 + 37 = 52$, and any arrangement with 1 and 3 in the tens places gives the same smallest sum.

## Check yourself

1. In 2,794, what is the value of the digit 7?

   - 7

   - 70

   - 700 ✔

   - 7000

   _Explanation:_ The 7 is in the hundreds column, so it is worth $7 \times 100 = 700$. Option B is the common mistake if you count the 7 as tens instead of hundreds. Hint: Count from the right: ones, tens, hundreds, thousands.

2. In 48.263, what is the value of the digit 6?

   - 0.6

   - 0.06 ✔

   - 6

   - 0.006

   _Explanation:_ The 6 is the second digit after the decimal point, so it is in the hundredths column and is worth $6 \times 0.01 = 0.06$. Option A is the common wrong answer because tenths is the first digit after the decimal point, not the second.

3. Which list puts these decimals in order from smallest to largest: 2.7, 2.07, 2.73, 2.703, 2.37?

   - 2.07, 2.37, 2.7, 2.703, 2.73 ✔

   - 2.07, 2.37, 2.703, 2.7, 2.73

   - 2.37, 2.07, 2.7, 2.703, 2.73

   - 2.07, 2.7, 2.37, 2.703, 2.73

   _Explanation:_ All the numbers have whole-number part 2. Write them as $2.070$, $2.370$, $2.700$, $2.703$, and $2.730$, then compare from left to right. Option B is the common mistake because it treats 2.703 as smaller than 2.7, but $2.7 = 2.700$, so 2.703 is larger.
