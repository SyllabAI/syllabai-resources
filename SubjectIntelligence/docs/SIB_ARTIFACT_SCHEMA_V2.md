# SIB Artifact Schema v2

**Status:** OPERATIONAL (2026-10-25, SIB-GEN program r0)
**Protocol:** SIB v1 (all v1 sections remain binding; this document defines the v2
provenance evolution and nothing else)
**Supersedes:** nothing — v1 (`SIB_ARTIFACT_SCHEMA_V1.md`) remains fully in force.
v2 is an **additive evolution**, not a replacement: no v1 required field is removed
or redefined, and every v1 artifact remains valid as-is.

## 0. Why v2 exists

The 4CH1 worked example was specified before any generation run happened, with
NotebookLM named as the primary generation provider. The operator has since directed
a provider change: subject-intelligence generation runs on the **zai_agent** class
(provider `z.ai`, SIB-GEN program tooling) with NotebookLM demoted to a legacy
provider reference (`SIB_NOTEBOOKLM_PROMPTS_V1.md`, retagged OPTIONAL-HIS).

A provider change must not corrupt provenance. Historical NotebookLM drops remain
valid under their original v1 provenance shape; new zai_agent runs get a provenance
shape that can actually express *how* an artifact was made (which run, which model,
which source revisions). The validator accepts both shapes — this is the **one-of
rule** (§3) — and owns all conversions, as always.

## 1. `generated_by` vocabulary (v2)

```
notebooklm | zai_agent | operator | agent | human
```

`zai_agent` is new in v2. The v1 values remain valid. A v2 artifact generated by
the SIB-GEN pipeline declares `generated_by: zai_agent`.

Consistency rule (binding): an artifact with `generated_by: zai_agent` MUST use the
v2 generator-shape provenance (§3). `notebooklm` artifacts may use either shape
(v1 notebook-shape for historical drops; v2 generator-shape is permitted and
preferred for any future NotebookLM run so it also gets run-manifest traceability).

## 2. What v2 does NOT change

Unchanged from v1, still fully binding:

- filename contract (`<SUBJECT>_<SPEC>_<ARTIFACT-ID>_<SLUG>.md`, §1 of v1);
- all 15 required front-matter fields (§2 of v1) — v2 only *extends* the
  `generated_by` vocabulary and the `provenance` mapping shape;
- publication lifecycle and status rules (§3 of v1);
- universal sections (§4), claim conventions (§5), current-vs-legacy labels (§6),
  record ids (§7), no-silent-normalization (§8), determinism (§9), chunking (§10),
  runtime eligibility (§11).

## 3. Provenance — the one-of rule

Every artifact's `provenance` mapping MUST match **exactly one** of the two shapes
below. Mixing shapes is a validation error. Matching neither is a validation error.

### 3.1 V1 notebook-shape (legacy, still valid)

```yaml
provenance:
  notebook: "<subject notebook identifier>"
  source_manifest: "<source manifest identifier>"
```

Both fields required; both must be concrete references (template placeholders are
rejected); `source_manifest` must be declared by the operator source manifest of the
library (validator cross-check, unchanged).

### 3.2 V2 generator-shape (new)

```yaml
generated_by: zai_agent
generated_at: 2026-10-25
provenance:
  source_manifest: "SRC-SPEC-4CH1"
  generation_run_id: "SIB-CHEMISTRY_4CH1-RUN-001"
  generator:
    provider: "z.ai"
    model: "<runtime-reported model identifier>"
    agent_version: "<generator program + revision, e.g. SIB-GEN-r0>"
  source_revisions:
    syllabai_resources: "<git commit sha>"
    syllabai_pastpapers: "<git commit sha>"
    syllabai_core: "<git commit sha, if used>"
```

Required fields:

| field | law |
|---|---|
| `source_manifest` | the operator source-manifest ENTRY id that anchors this artifact's identity (e.g. the official-specification source for a CUR artifact, the examiner-corpus source for an MIS artifact) — must be declared in the library's `source_manifest.yaml` (`sources:` id list); validator cross-check unchanged from v1. The FULL multi-source grounding lives in the run's evidence pack, referenced by `generation_run_id`. |
| `generation_run_id` | the run-manifest record id under `<LIBRARY>/runs/`; concrete, non-placeholder |
| `generator` | mapping with exactly the concrete sub-fields `provider`, `model`, `agent_version` (all three required; template placeholders rejected) |

Optional-but-standard field:

| field | law |
|---|---|
| `source_revisions` | mapping of repository name → git commit sha (7–40 hex chars) for every source repository the run actually read. The SIB-GEN run manifest is the authority for these values; the artifact mirrors them. A malformed sha is a validation error. |

Model identifiers are recorded from runtime truth — the pipeline records the
provider-reported model identity, never a guessed version string, and never an
operator identity substituted for a runtime one.

## 5. Validator semantics (summary)

The validator of record (`SyllabAI/syllabai@tools/sib/`) accepts both shapes:

- v1 notebook-shape → validated exactly as before (no behavior change);
- v2 generator-shape → required-field + concreteness + sha-shape checks as in §3.2;
- `generated_by: zai_agent` with v1 notebook-shape → error (provider/shape mismatch);
- both shapes present → error (ambiguous provenance);
- neither shape present → error (as before).

The validator never performs conversions itself and never drops required fields;
it only accepts or rejects. Conversion between shapes is a regeneration concern
owned by the run pipeline, and produces a new `artifact_version`.
